MiniMax-H3 请求参数

03 / MINIMAX H3

工作流由有无参考图片及 size 决定。seconds 使用整数 4–15；图片、视频与音频分别放入不同的顶层数组。

参数类型必填 / 范围使用方式
modelstring必填MiniMax-H3
promptstring必填，非空说明画面与素材作用；素材编号按各自数组顺序解释。
workflow_idstring必填text-to-video / multi-reference / cf-multi-reference，匹配规则见下节。
secondsinteger必填，4–15示例预设 5；不使用 duration。
sizestring必填采用尺寸表中的固定宽高值，或 2K / 4K。
aspect_ratiostring2K / 4K 时必填与所选画幅对应；固定宽高值省略本字段。
imagesstring[]最多 9 张公网图片 URL 字符串数组；可直接使用 gpt-image-2.5-flare 返回的 CDN 地址，见下方说明。两种参考工作流至少含 1 张图，空数组省略。
reference_videosstring[]最多 3 段公网视频 URL；使用参考视频时仍需至少 1 张图片。
reference_audiosstring[]最多 3 段公网音频 URL；使用参考音频时仍需至少 1 张图片。

H3 请求只发送对应字段：不附加 workflow_size、resolution、clarity、megapixels、mode、metadata.multiple、reference_video_audios、audio 或 prompt_enhance。非空素材数组才写入请求。

生图返回地址直接作为 H3 参考图

gpt-image-2.5-flare 生图文档使用 AIOSS 的异步生图对象存储接口：文生图 POST https://aioss.cc/v1/images/generations/async，参考图编辑 POST https://aioss.cc/v1/images/edits/async，并保留 response_format: "url"。取得可公开读取的存储图片地址后，可直接放入 H3 的 images 数组，无需先下载再上传，也无需与视频 API 使用同一域名。

  • 先等待任务完成：生图提交返回 202 仅表示受理。保存 task_id（没有时取 id），使用提交时同一把密钥 GET https://aioss.cc/v1/images/tasks/{task_id}。processing 时继续查询，failed 时处理错误，completed 后再创建视频任务。
  • 取原始 URL：异步完成任务读取 result.data[0].url，或顶层快捷字段 image_url。如果沿用同步生图结果，仍可读取 data[0].url / data[0].image_url。images 的每一项都是地址字符串，不传任务 ID、整个响应对象或本地文件名。
  • 保证上游可读取：地址必须能被 H3 上游通过公网 HTTP / HTTPS GET 直接获取真实图片，不依赖 Cookie、Authorization 或特定 Referer。浏览器登录后能打开不代表上游可读取；浏览器跨域下载限制与上游读取是两回事。
  • 保留完整地址：CDN URL 的签名、查询参数应原样保留，不替换为视频 API 域名；有效期需要覆盖任务排队及素材读取过程。AIOSS 配置公开存储域名时返回对象直链，否则可能返回有时限的签名 URL。图片 URL 有效期与生图任务记录的 expires_at 分别判断，以站点实际配置为准。
  • 区分本地引用：若从项目任务结果中取得 URL:https://…，先去掉内部的 URL: 前缀。IDB:、blob:、data:、本地路径、相对路径和本机地址不能直接交给 H3；应取得原始公网 CDN URL。仅返回 b64_json 时，需先将图片保存到可公开读取的存储并取得 URL。

先取得公网 URL

已有可公开读取的生图 CDN 地址可直接复用，详见生图返回地址接入说明。本地素材需先上传到业务存储或 CDN，再把无需登录即可读取的 HTTP / HTTPS 地址填入对应数组。视频可用 MP4 / WebM / MOV，音频可用 MP3 / WAV / M4A / AAC / OGG。

来源的临时上传服务是独立业务服务；其文件大小及保留时间不能作为 api.my110.vip 的上传限制。本页的生成接口使用 JSON URL 数组。

保持顺序与引用一致

V2 的 @Image1、@Video1、@Audio1 分别指向各数组第 1 项；中文标记可转换为上述英文标记。

H3 用“第 1 张参考图”等文字说明数组对应关系。每类去重时保持原有顺序，并按去重后的数组编号。本页会在发现引用越界时提示修正。

首尾帧模式只用于 v3：省略 images，仍可传入 videos 和 audios。H3 使用视频或音频参考时至少提供 1 张图片。

  • 统一读取任务对象如果响应的 data 是对象，读取 data；否则直接读取顶层。创建后优先保存 task_id，没有时保存 id。
  • 识别生成状态将 status 转成小写，success / succeeded / completed 表示成功；failed 表示失败。排队与处理中继续查询，超时保留 ID 后稍后恢复。
  • 优先使用返回的成片链接按 result_url → video_url → url → metadata.url 读取。链接使用原始返回值，下载外链不附加 API 密钥；没有外链时再携带 Bearer 调用 /content。
  • 及时保存来源文档提示结果缓存最多保留 48 小时；目标站具体保留期以实际服务为准。完成后及时下载或转存。
Python 轮询示例 · 已有任务每 5 秒查询
import time
from urllib.parse import quote
import requests


def wait_for_video(api_key, task_id, timeout_seconds=900):
    # 900 秒为调用方等待时间；到时保留任务 ID，可继续查询。
    deadline = time.monotonic() + timeout_seconds
    task_url = "https://api.my110.vip/v1/videos/" + quote(task_id, safe="")
    while time.monotonic() < deadline:
        response = requests.get(
            task_url,
            headers={"Authorization": f"Bearer {api_key}", "Accept": "application/json"},
            timeout=(15, 60),
        )
        response.raise_for_status()
        raw = response.json()
        task = raw["data"] if isinstance(raw.get("data"), dict) else raw
        status = str(task.get("status", "")).lower()
        if status in {"success", "succeeded", "completed"}:
            return task
        if status == "failed":
            raise RuntimeError(task.get("error") or task)
        remaining = deadline - time.monotonic()
        if remaining > 0:
            time.sleep(min(5, remaining))
    raise TimeoutError(f"请保存任务 ID 后继续查询：{task_id}")

常见问题与依据

10 / NOTES & SOURCES
问题检查项
H3 请求参数错误补齐 workflow_id、整数 seconds、正确 size；2K / 4K 搭配 aspect_ratio，固定像素值省略 aspect_ratio。
H3 视频 / 音频参考失败字段是 reference_videos 与 reference_audios，且至少提供 1 张 images。
V2 / V3 参数混用V2 使用 aspect_ratio，V3 使用 ratio；V3 为 4–29 秒、720p，使用顶层数组。
首尾帧请求失败V3 的 start_frame_url / end_frame_url 与 images 互斥；视频与音频数组可保留。
401 / 403 / 模型不可用确认 Bearer 密钥、账户模型权限及精确模型名。
任务未完成 / 请求超时保留 task_id，继续查询；已有任务不要重复 POST 创建。
没有 result_url依次尝试 video_url、url、metadata.url；成功但没有外链时使用同一任务的 /content。
